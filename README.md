# Goods & Services Acquisitions — GORE Callao (Q1 2026)

## Overview

This project cleans and validates a quarterly public procurement report
— *Órdenes giradas por clasificador* — published by the Gobierno
Regional del Callao (GORECALLAO), covering goods and services
acquisitions from January to March 2026. The raw file is exported in a
non-standard encoding (`cp850`) typical of government reporting
systems, and requires several standardization steps before it is
suitable for analysis.

## Data source

| Field | Detail |
|---|---|
| Dataset | Órdenes giradas por clasificador — Gobierno Regional del Callao (GORECALLAO) |
| Publisher | Gobierno Regional del Callao, via Peru's open data portal (datosabiertos.gob.pe) |
| File | `ADQUISICION_DE_BIENES_Y_SERVICIOS_ENERO_A_MARZO_2026.csv` |
| Period | January – March 2026 |
| Rows | 2,498 |
| Columns | 19 |
| Encoding | `cp850` |
| Delimiter | `,` |

## Usage

1. Place the raw CSV file in `data/raw/`.
2. Open `notebooks/exploracion_adquisicion.ipynb` and run all cells.
3. The cleaned dataset is written to `data/processed/adquisicion_bienes_2026_q1_clean.csv`.

The notebook imports the cleaning logic from `src/clear_script.py`, so the
function can also be reused directly in other scripts:

```python
from clear_script import clear_script

df = clear_script("data/raw/ADQUISICION_DE_BIENES_Y_SERVICIOS_ENERO_A_MARZO_2026.csv")
```

## Cleaning steps

`clear_script()` applies the following transformations, in order:

1. Reads the file with the correct encoding (`cp850`) and delimiter (`,`).
2. Normalizes column names to lowercase.
3. Strips leading and trailing whitespace from all text columns.
4. Parses `fecha_orden` into a proper date, discarding the redundant
   time component (always `00:00:00` in the source file).
5. Casts `nro_ruc` to string, since it is an identifier, not a quantity.
6. Standardizes casing in `fase_orden` and `tipo_bien` using title case.
7. Converts `fase_orden`, `tipo_bien`, and `tipo_proceso` to the
   `category` dtype, since they represent a fixed set of coded values.
8. Unifies inconsistent null representations in `nro_proc_sel`
   (literal `"."` and `"0"` values are treated as missing, in addition
   to actual `NaN`).

## Data quality checks

The notebook validates three issues identified during exploratory
analysis, each backed by an assertion that stops execution if the
expected condition is not met:

1. **Whitespace in `nombre_prov`.** Confirms that no provider name has
   stray leading or trailing spaces after cleaning.
2. **Null unification in `nro_proc_sel`.** Reports the resulting
   percentage of missing values (expected around 94%, since this field
   only applies to procurement types that require a formal selection
   process).
3. **Negative amounts in `total_fact_moneda`.** Confirms that every
   negative value corresponds to an order in the `Rebaja` or `Anulado`
   phase, meaning negative amounts represent legitimate rebates or
   cancellations rather than data entry errors.

## Known limitations

- The cleaning function assumes the same column layout as the January–
  March 2026 file. If a future report adds, removes, or renames columns,
  the assertions in the notebook will fail and should be reviewed before
  trusting the output.
- `nro_proc_sel` remains unpopulated for most rows by design (procurement
  types that do not require a formal selection process). This is
  structural missingness, not a data quality defect, and should not be
  imputed.
